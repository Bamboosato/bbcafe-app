# BB Cafe 自動送信・画面設定 仕様書

2026-10-06時点の実装に合わせて改訂。認証はFirebase Auth、ナビゲーション全体は[ホーム仕様](./home-screen-spec.md)、管理設定は[管理画面仕様](./admin-integration-spec.md)を参照する。

## 1. 目的

BB Cafe Messages の閲覧画面に、受信履歴、送信履歴、ユーザ情報、メッセージ送信の画面を分離して配置する。

あわせて、ユーザ情報画面で選択したユーザを永続的なブロードキャスト対象として保存し、毎朝の自動送信、手動送信、送信履歴、送信結果のPush通知を扱えるようにする。

## 2. テスト観点一覧

詳細ケースを書く前に、以下の観点を満たすことを確認する。

| 観点 | 確認すること |
| --- | --- |
| 機能観点 | PCのタブ、スマホのハンバーガーメニュー、受信履歴、送信履歴、ユーザ選択保存、手動送信、自動送信、Push通知が要求通り動くこと |
| 非機能観点 | Vercel Cronの時刻ずれ、Fluid Compute前提の実行時間、外部API遅延、LINE API失敗、Push通知失敗、重複実行に耐えること |
| データ観点 | ユーザ情報、選択状態、自動送信設定、送信履歴、失敗詳細、保存期限がFirestoreで一貫して保持されること |
| UI観点 | PCとスマホでナビゲーションが破綻しないこと、送信対象と自動送信状態が誤解なく読めること、長文や空状態が崩れないこと |
| 実行観点 | 単体成功でも通しで失敗するケース、実行順序依存、非同期競合、同日Cron重複、手動送信中の二重クリックを切り分けられること |

## 3. 確定方針

| 項目 | 方針 |
| --- | --- |
| 対象画面 | Firebase Authでログインした本人のアカウントの閲覧・配信画面 |
| PCナビゲーション | URL付きタブ |
| スマホナビゲーション | アカウントアイコンの右側にハンバーガーメニューを表示 |
| アカウントアイコン | 通知設定、ログアウトなどアカウント操作用に残す |
| 受信履歴 | 既存ホーム画面の受信メッセージ一覧 |
| 送信履歴 | 1回の一斉送信を1行として表示 |
| ユーザ情報 | 一度保存されたユーザは自動削除しない |
| 選択状態 | Firestoreに永続化し、自動送信の正式な送信対象にする |
| メッセージ送信 | 永続化された選択ユーザの全員、または今回選んだ一部へ送信する |
| 自動送信 | 初期状態はOFF |
| 自動送信時刻 | 日本時間 07:00 固定。変更する場合は再デプロイ |
| Vercel Cron精度 | Hobbyプランの時刻ずれは許容する |
| Function実行時間 | Fluid Compute有効を前提にする |
| 送信履歴保存期間 | 受信履歴とは別設定、既定180日。管理画面で変更可能 |
| 自動再送 | 実施しない。失敗は送信履歴に残す |
| 自動送信後Push通知 | 通知ONの全端末へ、本文なしで成功/失敗サマリーを通知 |

## 4. 対象外

- 正式な配信対象に含まれないユーザへの手動送信。
- 画面からの自動送信時刻変更。
- 自動送信失敗時の自動再送。
- 送信履歴のCSV出力。
- 送信本文のPush通知本文への表示。
- 厳密な07:00ちょうどの送信保証。

## 5. 画面仕様

### 5.1 ルーティング

| URL | 画面 | 備考 |
| --- | --- | --- |
| `/` | ホーム | 未確認メッセージと当日の運用状況を表示 |
| `/messages` | 受信履歴 | LINE公式アカウントへ届いたメッセージ履歴 |
| `/sent` | 送信履歴 | 手動送信、自動送信の履歴を表示 |
| `/cron-runs` | Cron履歴 | 3種類の自動処理の履歴 |
| `/users` | ユーザ情報 | 永続化されたユーザと選択状態を表示 |
| `/send` | メッセージ送信 | 手動送信と自動送信設定を表示 |
| `/calendar` | カレンダー情報 | 月日イベント |
| `/settings` | 管理画面 | LINE連携・保存期間・外部情報 |

未ログインで各URLを開いた場合はログイン画面を表示する。ログイン成功後は、アクセスしていたURLの画面を表示する。

### 5.2 PC表示

PC幅ではヘッダー下またはヘッダー内に以下のタブを表示する。

| タブ | URL |
| --- | --- |
| ホーム | `/` |
| 受信履歴 | `/messages` |
| 送信履歴 | `/sent` |
| Cron履歴 | `/cron-runs` |
| ユーザ情報 | `/users` |
| メッセージ送信 | `/send` |
| カレンダー情報 | `/calendar` |
| 管理画面 | `/settings` |

現在のURLに対応するタブを選択状態にする。タブ移動ではログイン状態、Push通知設定、既存の受信履歴更新処理が壊れないようにする。

### 5.3 スマホ表示

スマホ幅ではPCタブを隠し、ヘッダー右側に以下の順でアイコンを表示する。

```text
アカウントアイコン  ハンバーガーメニュー
```

ハンバーガーメニューには以下を表示する。

- ホーム
- 受信履歴
- 送信履歴
- Cron履歴
- ユーザ情報
- メッセージ送信
- カレンダー情報
- 管理画面

アカウントアイコン側には、通知設定とログアウトを残す。ユーザ情報、メッセージ送信などの画面遷移項目はハンバーガーメニュー側へ移す。

### 5.4 受信履歴

既存の受信メッセージ一覧を維持する。

- 受信メッセージ一覧。
- メッセージ種別フィルター。
- 60秒ごとの自動更新。
- Push通知クリック後の即時更新。
- メッセージ詳細モーダル。
- 1ページ既定20件、追加読み込み。フィルターは読み込んだ履歴に適用する。

### 5.5 送信履歴

1回の一斉送信を1行として表示する。

表示項目:

- 送信日時。
- 送信種別: `手動` または `自動`。
- ステータス: `成功`、`一部失敗`、`失敗`。
- 送信先人数。
- 成功件数。
- 失敗件数。
- 本文プレビュー。
- 失敗ユーザ詳細。

本文全文と失敗ユーザ詳細は、行の展開または詳細モーダルで確認できるようにする。

空状態:

```text
送信履歴はありません。
```

### 5.6 ユーザ情報

既存のユーザ情報画面をベースにする。ただし、ユーザ一覧は受信メッセージから都度抽出するのではなく、Firestoreに保存されたユーザ情報を表示する。

表示項目:

- 選択チェックボックス。
- アカウント名。
- USER ID。
- 初回保存日時。
- 最終確認日時。

選択チェックボックスは自動送信と手動送信の送信対象を表す。変更はFirestoreへ永続化する。保存失敗時は画面にエラーを表示し、失敗した変更が送信対象として扱われないようにする。

ユーザはテキスト受信・友だち追加のWebhook、既存受信からの補完、`友だち取り込み`で保存する。取り込みはLINE側で取得可能な友だちIDとプロフィールを利用する。取得失敗・制限は画面に表示し、既存の選択状態を取り込みで変更しない。

新しく保存されるユーザの初期選択状態はOFFにする。

### 5.7 メッセージ送信

既存の手動メッセージ作成、編集、送信画面をベースにする。

送信対象:

- `/users` で選択状態がONのユーザ。
- その集合から今回送るユーザだけをチェックで選択できる。正式な選択状態や自動送信対象は変更しない。

表示項目:

- 作成ボタン。
- 送信ボタン。
- メッセージ本文。
- 対象地域。
- 送信対象人数とユーザ名。
- ユーザ情報画面への導線。
- 自動送信設定。

送信ボタンは、本文が空、送信対象が0件、生成中、送信中の場合に無効化する。

### 5.8 自動送信設定

`/send` 画面内に `自動送信設定` セクションを置く。

表示項目:

| 項目 | 初期値 | 編集 |
| --- | --- | --- |
| 自動送信 | OFF | 可能 |
| 送信時刻 | 07:00 | 初回は画面編集不可 |
| タイムゾーン | 日本時間 | 画面編集不可 |
| 送信履歴保存期間 | 180日 | `/send`では表示のみ。管理画面で編集可能 |

送信時刻を変更する場合は、`vercel.json` のCron設定を変更して再デプロイする。

## 6. データ仕様

### 6.1 ユーザ情報

保存先:

```text
lineAccounts/{lineAccountId}/users/{userId}
```

保存例:

```json
{
  "broadcastSelected": false,
  "createdAt": "...",
  "firstSeenAt": "...",
  "lastMessageAt": "...",
  "lastSeenAt": "...",
  "lineAccountId": "default",
  "updatedAt": "...",
  "userId": "Uxxxxxxxx",
  "userName": "山田太郎"
}
```

ルール:

- Webhookで `sourceUserId` を取得できた場合にupsertする。
- 既存の受信メッセージから取得できるユーザは、初回移行またはユーザ情報取得時にbackfillする。
- `userName` は最新確認時の表示名で更新してよい。
- `broadcastSelected` は自動更新で変更しない。
- ユーザは保存期間や受信履歴削除に連動して自動削除しない。

### 6.2 自動送信設定

保存先:

```text
lineAccounts/{lineAccountId}/automationSettings/dailyBroadcast
```

保存例:

```json
{
  "enabled": false,
  "externalCareSignalsEnabled": false,
  "historyRetentionDays": 180,
  "lineAccountId": "default",
  "scheduleMode": "fixed_deploy",
  "sendTimeJst": "07:00",
  "timeZone": "Asia/Tokyo",
  "updatedAt": "..."
}
```

ルール:

- 初期状態は `enabled: false`。
- Cronは毎日呼ばれるが、`enabled: false` の場合は送信せずに終了する。
- `sendTimeJst` は初回は表示用。変更する場合は再デプロイが必要。
- `historyRetentionDays` は初期値180日。
- `externalCareSignalsEnabled`は初期OFF。管理画面で更新し、手動作成と自動配信で共有する。感染症注意情報の表示履歴もこの設定文書に保持する。

### 6.3 送信履歴

保存先:

```text
lineAccounts/{lineAccountId}/sendRuns/{runId}
```

保存例:

```json
{
  "createdAt": "...",
  "expiresAt": "...",
  "failedCount": 1,
  "finishedAt": "...",
  "historyRetentionDays": 180,
  "lineAccountId": "default",
  "messageText": "お早うございます。\n...",
  "mode": "auto",
  "requestId": "req_xxx",
  "runId": "send_...",
  "sentAt": "...",
  "startedAt": "...",
  "status": "partial_failed",
  "successCount": 9,
  "targetCount": 10,
  "targets": [
    {
      "status": "success",
      "userId": "Uxxxxxxxx",
      "userName": "山田太郎"
    },
    {
      "errorCode": "LINE_400",
      "httpStatus": 400,
      "status": "failed",
      "userId": "Uyyyyyyyy",
      "userName": "佐藤花子"
    }
  ],
  "trigger": "cron",
  "updatedAt": "..."
}
```

`status` の値:

| 値 | 意味 |
| --- | --- |
| `success` | 全件成功 |
| `partial_failed` | 一部失敗 |
| `failed` | 全件失敗、または送信処理自体が失敗 |

`mode` の値:

| 値 | 意味 |
| --- | --- |
| `manual` | 手動送信 |
| `auto` | 自動送信 |

ルール:

- 送信開始時点の送信対象をスナップショットとして保存する。
- 後からユーザ名や選択状態が変わっても、過去の送信履歴は変えない。
- `expiresAt` は `sentAt + historyRetentionDays` とする。
- 送信履歴の物理削除は既存の期限切れ削除Cronに統合する。

## 7. API仕様

### 7.1 アカウントAPI

すべてFirebase Authから発行した`bbcafe_auth_v2`で本人の内部アカウントを認証する。

| Method | Path | 用途 |
| --- | --- | --- |
| `GET` | `/api/users` | 永続化されたユーザ情報と選択状態を取得 |
| `GET` | `/api/users/summary` | 選択人数を取得 |
| `POST` | `/api/users/import-line-followers` | 友だち情報を取り込み |
| `PATCH` | `/api/users/{userId}` | 選択状態を更新 |
| `GET` | `/api/sent-messages` | 送信履歴を取得 |
| `GET` | `/api/message-assistant/automation-settings` | 自動送信設定を取得 |
| `PATCH` | `/api/message-assistant/automation-settings` | 自動送信ON/OFFを更新 |
| `POST` | `/api/message-assistant/generate` | 既存通りメッセージを作成 |
| `POST` | `/api/message-assistant/send` | 永続化された選択ユーザへ手動送信し、送信履歴を保存 |

`POST /api/message-assistant/send`は`message`と任意の`userIds`、感染症注意情報を含む場合の`infectionNoticeKey`を受け取る。正式な送信対象はFirestore上の`broadcastSelected: true`から取得し、`userIds`指定時はその集合内のユーザへ絞る。未指定は全員、空配列・対象外IDは400。IDはトリム・重複除去する。クライアント指定だけで未選択ユーザを送信対象へ追加しない。

```json
{
  "message": "お早うございます。...",
  "userIds": ["Uxxxxxxxx"]
}
```

### 7.2 Cron API

| Method | Path | 用途 |
| --- | --- | --- |
| `GET` | `/api/cron/send-daily-message` | 自動送信 |

Request header:

```http
Authorization: Bearer <CRON_SECRET>
```

認証失敗時は送信しない。

### 7.3 vercel.json

日本時間07:00はUTC前日22:00のため、以下を設定している。

```json
{
  "path": "/api/cron/send-daily-message",
  "schedule": "0 22 * * *"
}
```

Hobbyプランでは日次Cronの時刻ずれを許容する。厳密な時刻制御が必要になった場合は、Proプランで高頻度Cronにしてアプリ側で時刻判定するか、外部スケジューラを検討する。

## 8. 自動送信処理

### 8.1 処理フロー

```text
1. CRON_SECRETを検証する
2. 有効なLINEアカウントを取得し、各アカウントを順に処理してdailyBroadcast設定を取得する
3. enabled=falseなら送信せず終了する
4. 日本時間の日付で自動送信用runIdを決める
5. runIdを作成予約する。既に存在する場合はalready_ranで終了する
6. broadcastSelected=trueのユーザを取得する
7. 送信対象が0件なら失敗履歴を保存して終了する
8. 既存のメッセージ作成処理と同じ内容で本文を生成する
9. LINEへ送信する
10. 成功件数、失敗件数、失敗詳細をsendRunsに保存する
11. 自動送信結果のPush通知を送る
```

### 8.2 重複送信防止

自動送信のrunIdは、lineAccountIdと日本時間の日付から決める。

```text
auto_{lineAccountId}_{yyyyMMdd}
```

同じrunIdの履歴が存在する場合は送信しない。Vercel Cronの再実行、手動再アクセス、ネットワーク再試行があっても同日に二重送信しないことを優先する。

予約はFirestoreのdocument createで競合を防ぐ。生成失敗・対象0件・配信失敗でも同日予約は残り、Cron再実行で再送しない。初期予約は`status=failed`、`finishedAt=null`であり、処理中断時にこの状態が残り得る。必要な再送は送信履歴で対象を確認して手動で行う。

### 8.3 失敗時の扱い

- 自動再送はしない。
- 送信処理が失敗した場合も、可能な限り送信履歴に失敗として残す。
- 一部ユーザだけ失敗した場合は `partial_failed` として残す。
- 全件失敗または本文生成に失敗した場合は `failed` として残す。
- Push通知失敗は自動送信自体の失敗にはしない。ログに残す。

## 9. Push通知仕様

自動送信が完了したタイミングで、同じLINEアカウントに紐づく通知登録端末へWeb Pushを送る。

通知本文に送信メッセージ本文は含めない。

成功時:

```text
自動送信が完了しました（成功X件 / 失敗0件）
```

一部失敗時:

```text
自動送信が完了しました（成功X件 / 失敗Y件）
```

全件失敗時:

```text
自動送信に失敗しました（成功0件 / 失敗Y件）
```

通知クリック時の遷移先は `/sent` とする。

## 10. 送信履歴削除

送信履歴は既定180日保存する。管理画面の保存期間変更は新規作成の履歴へ適用し、既存の`expiresAt`は変更しない。

削除対象:

```text
lineAccounts/{lineAccountId}/sendRuns/{runId}
expiresAt <= now
```

期限切れメッセージ削除Cronで、アカウントごとに送信履歴を最大200件削除する。受信履歴の直近1000件保護は送信履歴には適用しない。API応答は送信履歴削除件数・失敗件数を返すが、現行の受信削除履歴と統合Cron画面のサマリーにはこの件数を保存しない。

## 11. テストケース

### 11.1 正常系

| Case | 対象 | 意図 |
| --- | --- | --- |
| N-001 | PCナビゲーション | 8タブで各URLへ移動でき、選択状態がURLと一致する |
| N-002 | スマホナビゲーション | アカウントアイコン右側のハンバーガーから8画面へ移動できる |
| N-003 | 受信履歴 | 既存の受信一覧、フィルター、詳細表示が維持される |
| N-004 | ユーザ保存 | Webhook受信時にsourceUserIdをユーザ情報として保存できる |
| N-005 | ユーザbackfill | 既存メッセージからユーザ情報を初回保存できる |
| N-006 | 選択保存 | ユーザ選択状態をFirestoreに保存し、リロード後も維持できる |
| N-007 | 手動送信 | 選択済みユーザに送信し、送信履歴を1行保存できる |
| N-008 | 送信履歴 | 手動送信と自動送信を送信種別付きで表示できる |
| N-009 | 自動送信OFF | Cronが呼ばれても送信せず終了できる |
| N-010 | 自動送信ON | 選択済みユーザに07:00台Cronで自動送信できる |
| N-011 | Push通知 | 自動送信完了後に成功/失敗サマリー通知を送れる |
| N-012 | 手動対象絞り込み | 正式対象の一部だけ送信し、正式選択と自動送信対象を変更しない |

### 11.2 異常系

| Case | 対象 | 意図 |
| --- | --- | --- |
| E-001 | Cron認証 | CRON_SECRET不一致なら自動送信しない |
| E-002 | 選択保存 | Firestore更新失敗時にエラー表示し、保存済み状態と画面状態を矛盾させない |
| E-003 | 手動送信 | 本文空なら送信しない |
| E-004 | 手動送信 | 送信対象0件なら送信しない |
| E-005 | 自動送信 | 送信対象0件なら失敗履歴を残し、LINE送信しない |
| E-006 | 本文生成 | 生成処理が最終的に失敗した場合は失敗履歴を残す。利用可能な情報で縮退生成できる外部情報障害と区別する |
| E-007 | LINE送信 | 一部ユーザのLINE送信失敗を履歴の失敗詳細に残す |
| E-008 | Push通知 | Push通知失敗でも送信履歴保存結果を失敗にしない |
| E-009 | 対象外userIds | 正式対象外のIDを渡すと400になり、LINE送信しない |

### 11.3 境界値

| Case | 対象 | 意図 |
| --- | --- | --- |
| B-001 | ユーザ数0 | ユーザ情報、送信画面、自動送信が空状態を正しく扱う |
| B-002 | 選択ユーザ0 | 手動送信ボタンが無効になり、自動送信は失敗履歴を残す |
| B-003 | 送信履歴0 | `/sent` に空状態を表示する |
| B-004 | 送信履歴保存期間 | `sentAt + 設定日数` を `expiresAt` として保存する。既定180日 |
| B-005 | 同日Cron重複 | 同じ日本日付のCronが複数回呼ばれても二重送信しない |
| B-006 | 長文本文 | 送信履歴一覧ではプレビュー、詳細では全文を崩さず表示する |
| B-007 | 失敗ユーザ多数 | 失敗詳細がUIを壊さず確認できる |

### 11.4 状態遷移

| Flow | 意図 |
| --- | --- |
| 未ログイン -> `/sent` 直アクセス -> ログイン -> `/sent` 表示 | URL付き画面で認証後の復帰ができる |
| 新規ユーザ受信 -> ユーザ情報保存 -> 選択ON -> 手動送信 | ユーザ保存から手動送信まで一貫する |
| 選択ON -> リロード -> 選択ON維持 | 選択状態がReact stateだけに依存しない |
| 自動送信OFF -> Cron -> 送信なし | 初期OFFで誤送信しない |
| 自動送信ON -> Cron -> 送信履歴保存 -> Push通知 | 自動送信の主要フローが通る |
| 自動送信ON -> LINE一部失敗 -> 履歴partial_failed -> Push通知 | 失敗を再現可能な形で残す |
| 同日Cron成功 -> 同日Cron再実行 -> skip | 重複実行で二重送信しない |
| 同日Cron予約 -> 生成／配信失敗 -> 再実行 -> already_ran | 失敗後も自動再送せず、手動対応が必要である |
| 送信履歴作成 -> 180日経過 -> 削除Cron -> 履歴削除 | 保存期間が受信履歴と独立して動く |

### 11.5 実行順序と証跡

- ユーザ保存、選択保存、手動送信、自動送信は単体テストと通しテストを分ける。
- Cronの重複実行テストは、同じ実機や同じ本番LINEアカウントへ並列実行しない。
- 失敗時は `requestId`、`runId`、`lineAccountId`、`mode`、`status`、`targetCount`、`successCount`、`failedCount`、失敗ユーザの `userId` とHTTP statusを確認できるようにする。
- パスワード、LINE channel secret、LINE channel access token、Cookie値、Push subscription keysはログに出さない。

## 12. 受け入れ条件

- PCでは8タブ、スマホではハンバーガーメニューで8画面へ移動できる。
- アカウントアイコンは通知設定とログアウト用に残っている。
- `/`はホーム、受信履歴は`/messages`で利用できる。
- ユーザ情報はFirestoreに保存され、受信履歴削除では自動削除されない。
- ユーザ選択状態はリロード、別端末、再ログイン後も維持される。
- 手動送信は永続化された選択ユーザの全員、またはその中の今回選んだ一部へ送信される。
- 手動送信と自動送信が送信履歴に1行単位で保存される。
- 送信履歴の保存期間は既定180日で、管理画面の変更は新規履歴へ適用される。
- 自動送信は初期OFFで、ONの場合のみ07:00台のCronで送信される。
- 同じ日本日付で自動送信が重複実行されない。
- 自動送信の失敗は自動再送されず、送信履歴に残る。
- 自動送信完了後、通知ONの端末に本文なしの成功/失敗サマリーPush通知が届く。
