# BB Cafe Messages ホーム画面 仕様書

## 1. 目的

BB Cafe Messages にホーム画面を追加し、日常運用で最初に確認すべき情報を集約する。

最重要目的は、送信したLINEメッセージに対して相手が確認ボタンを押していない状態を見落とさないことである。ホーム画面は説明ページではなく、未確認メッセージのフォローと当日の運用状況確認に使うダッシュボードとする。

## 2. 用語

| 用語 | 定義 |
| --- | --- |
| 未確認メッセージ | 送信したLINEメッセージに対して、送信先ユーザが確認ボタンを押していないもの |
| 未確認対象 | `confirmationStatus` が `pending` または `reminded` の送信成功ユーザ |
| 通知済み | 未確認通知Cronにより管理者/閲覧者へPush通知済みの未確認対象 |
| 未確認カード | 未確認メッセージがある場合だけホーム上部に表示する注意カード |

## 3. 画面方針

- ホーム画面は、ログイン後に最初に確認する運用ダッシュボードとする。
- 未確認メッセージがある場合は、他のショートカットやステータスよりも先に未確認カードを表示する。
- 未確認メッセージがない場合は、未確認カードを表示しない。
- 未確認がない通常時にも、ステータスカード上では `未確認 0件` または `確認待ちはありません` として状態を確認できるようにする。
- 上部の常設ショートカットは状態によって切り替えない。

## 4. タブ・ルート

ホーム画面を追加する場合、タブの先頭に `ホーム` を置く。

| 順序 | タブ | URL | 役割 |
| --- | --- | --- | --- |
| 1 | ホーム | `/` | 未確認メッセージと当日の運用状況 |
| 2 | 受信履歴 | `/messages` | LINE公式アカウントへ届いたメッセージ履歴 |
| 3 | 送信履歴 | `/sent` | 手動送信、自動送信の履歴と確認状況 |
| 4 | Cron履歴 | `/cron-runs` | 自動処理の実行結果 |
| 5 | ユーザ情報 | `/users` | 送信対象ユーザの確認と選択 |
| 6 | メッセージ送信 | `/send` | Gemini作成文の手動作成と送信 |
| 7 | カレンダー情報 | `/calendar` | 月日とイベント文の管理 |
| 8 | 管理画面 | `/settings` | 共通設定 |

## 5. 表示仕様

### 5.1 上部ショートカット

ホーム画面上部には、常設ショートカットとして次の2つを表示する。

| ボタン | 遷移先 | 表示条件 |
| --- | --- | --- |
| メッセージ作成 | メッセージ送信 | 常に表示 |
| 受信履歴を確認 | 受信履歴 | 常に表示 |

未確認メッセージの有無によって、上部ショートカットの内容や順序は変更しない。

未確認対応の導線は、未確認カード内の `送信履歴で確認` に集約する。

### 5.2 未確認カード

未確認カードは、未確認メッセージが1件以上ある場合だけ表示する。

表示位置は次の通りとする。

| 画面幅 | 表示位置 |
| --- | --- |
| PC | タイトル/サブタイトル/上部ショートカットの下、ステータスカード群より上 |
| モバイル | タイトル/サブタイトルの直下。上部ショートカットより上 |

モバイルでは、未確認メッセージの見落とし防止を優先するため、`メッセージ作成` と `受信履歴を確認` より先に未確認カードを表示する。

未確認カードには次の情報を表示する。

| 項目 | 内容 |
| --- | --- |
| タイトル | `未確認メッセージがあります` |
| 件数 | 未確認対象の人数または件数 |
| 説明 | `確認ボタンが押されていない送信先` |
| 対象者 | 未確認対象ユーザ名。多すぎる場合は代表者 + `ほかN名` |
| 最終確認チェック | 直近の未確認チェック時刻、通知済み人数 |
| 主操作 | `送信履歴で確認` |
| 副操作 | 必要に応じて `Cron履歴` |

`送信履歴で確認` は、送信履歴画面へ遷移し、確認状況を確認できる導線とする。

### 5.3 ステータスカード

未確認カードとは別に、当日の運用状況を要約するステータスカードを表示する。

表示候補は次の通り。

| カード | 表示内容 |
| --- | --- |
| 今日の自動送信 | 成功/失敗/未実行、送信時刻、対象数、成功数、失敗数 |
| 未確認フォロー | 未確認0件、通知済み、未実行、失敗など |
| 今日のカレンダー情報 | 当日イベントの有無 |
| Cron履歴 | 直近Cronの正常/注意あり/失敗 |

未確認メッセージがある場合、`未確認フォロー` と `Cron履歴` は注意状態として見えるようにする。

### 5.4 未確認対象一覧

未確認メッセージがある場合は、未確認カードの下にも詳細一覧を表示する。

表示項目は次の通り。

| 項目 | 内容 |
| --- | --- |
| ユーザ名 | 未確認対象ユーザ名 |
| 送信日時 | 対象となるLINEメッセージの送信日時 |
| 状態 | 未確認 / 未確認（通知済み） |

一覧の右上または下部に `送信履歴` ボタンを置き、詳細確認へ移動できるようにする。

### 5.5 直近の送信

直近の送信履歴を数件表示する。

これは未確認フォローの補助情報であり、未確認カードより優先しない。

## 6. レスポンシブ仕様

### 6.1 PC

PCでは、次の順序で表示する。

1. ヘッダー
2. タブ
3. ホームタイトル、サブタイトル、常設ショートカット
4. 未確認カード（未確認がある場合のみ）
5. ステータスカード
6. 未確認対象一覧、直近の送信

### 6.2 モバイル

モバイルでは、次の順序で表示する。

1. ヘッダー
2. ホームタイトル、サブタイトル
3. 未確認カード（未確認がある場合のみ）
4. 常設ショートカット（`メッセージ作成`、`受信履歴を確認`）
5. ステータスカード
6. 未確認対象一覧
7. 直近の送信

モバイルでは、未確認カードを常設ショートカットより上に置く。これは、未確認メッセージのフォローを最優先の操作として扱うためである。

## 7. データ仕様

ホーム画面では、既存の送信履歴と確認対象データを利用する。

| 情報 | 参照元 |
| --- | --- |
| 未確認対象 | 最新の確認対象データ |
| 未確認通知状況 | 未確認通知Cronの実行結果 |
| 今日の自動送信 | 送信履歴 |
| 今日のカレンダー情報 | カレンダー情報 |
| Cron履歴 | Cron履歴 |
| 直近の送信 | 送信履歴 |

未確認対象の判定は、送信成功ユーザのうち `confirmationStatus` が `pending` または `reminded` のものとする。送信失敗ユーザは未確認対象に含めない。

## 8. テスト観点

### 8.1 機能観点

| ID | 観点 | 意図 |
| --- | --- | --- |
| H-001 | 未確認あり | 未確認カードが表示されること |
| H-002 | 未確認なし | 未確認カードが表示されないこと |
| H-003 | ショートカット固定 | 未確認有無で上部ショートカットが変わらないこと |
| H-004 | 送信履歴導線 | 未確認カード内の `送信履歴で確認` から送信履歴へ移動できること |
| H-005 | モバイル順序 | モバイルで未確認カードがショートカットより上に表示されること |

### 8.2 データ観点

| ID | 観点 | 意図 |
| --- | --- | --- |
| H-101 | pending | `pending` が未確認件数に含まれること |
| H-102 | reminded | `reminded` が未確認件数に含まれること |
| H-103 | confirmed | `confirmed` が未確認件数に含まれないこと |
| H-104 | not_required | `not_required` が未確認件数に含まれないこと |
| H-105 | 送信失敗 | 送信失敗ユーザが未確認件数に含まれないこと |

### 8.3 UI観点

| ID | 観点 | 意図 |
| --- | --- | --- |
| H-201 | 強調表示 | 未確認ありの注意カードが他のカードより目立つこと |
| H-202 | 通常時 | 未確認0件の通常時に画面が過度に警告表示にならないこと |
| H-203 | PC表示 | PCでタブ、ショートカット、未確認カード、ステータスカードが重ならないこと |
| H-204 | モバイル表示 | モバイルで未確認カードがファーストビュー内に収まりやすいこと |
| H-205 | 長い名前 | 対象者名が長い場合でもレイアウトが崩れないこと |

### 8.4 状態遷移

| ID | 状態 | 期待結果 |
| --- | --- | --- |
| H-301 | 未確認0件 -> 未確認発生 | ホーム上部に未確認カードが表示される |
| H-302 | 未確認発生 -> 通知済み | 件数は残り、状態が通知済みとして表示される |
| H-303 | 未確認あり -> 全員確認済み | 未確認カードが消える |
| H-304 | Cron失敗 | Cron履歴カードが注意または失敗として表示される |

## 9. 優先度

まず防ぐべき不具合は、未確認メッセージがあるにもかかわらずホームで見落とすことである。

そのため、初回実装では次を優先する。

1. 未確認カードの表示/非表示
2. 未確認件数と対象者名の表示
3. `送信履歴で確認` 導線
4. モバイルで未確認カードを最上位に表示すること
5. ステータスカードと直近送信の表示
