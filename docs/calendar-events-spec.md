# BB Cafe カレンダー情報 仕様書

## 1. 目的

BB Cafe Messages の挨拶文作成時に、日付に紐づく誕生日や記念日を「今日の大切な予定」としてGeminiへ渡せるようにする。

カレンダー情報はユーザ情報に紐づけず、月日とフリーテキストで保存する。目的は、全員向けに送信する共通メッセージの中で、その日の誕生日や記念日を最優先の話題として扱うことである。

例:

```text
07/29  千夏子の誕生日
10/19  岳夫の誕生日
10/31  由美子の誕生日
11/09  岳夫と由美子の結婚記念日
```

## 2. テスト観点一覧

詳細ケースを書く前に、以下の観点を満たすことを確認する。

| 観点 | 確認すること |
| --- | --- |
| 機能観点 | カレンダー情報の追加、編集、削除、有効/無効切り替え、当日イベント取得、Geminiプロンプト反映、手動生成と自動送信の両方で同じイベントを扱えること |
| 非機能観点 | Firestore読み取り回数、Cron実行時間、Gemini API遅延、LINE送信失敗、日付判定の時刻ずれ、同時編集に耐えること |
| データ観点 | `lineAccountId` ごとの分離、月日正規化、フリーテキストのトリム、無効イベント除外、同日複数イベント、存在しない日付、2月29日を扱えること |
| UI観点 | PCとスマホで一覧、追加、編集、削除が破綻しないこと、今日Geminiに渡る予定を送信前に確認できること、入力エラーが保存前に分かること |
| 実行観点 | 単体では成功し通しで失敗するケース、手動生成とCron自動送信の差、非同期保存中の二重操作、再現手順とログを取得できること |

## 3. 確定方針

| 項目 | 方針 |
| --- | --- |
| 用途 | 全員向け共通メッセージの優先ネタ |
| 紐づけ | ユーザではなく日付に紐づける |
| 入力形式 | 月日 + フリーテキスト |
| 対象日 | 年を持たない毎年繰り返しの月日 |
| Geminiへの渡し方 | 当日に一致する有効イベントを「今日の大切な予定」として渡す |
| 優先順位 | 当日イベントがある場合は、誕生花、花言葉、天気、季節の話題より優先する |
| 送信本文 | 現行どおり1つの本文を生成し、選択済みユーザ全員へ同じ内容で送る |
| 送信履歴 | 現行どおり1回の送信を1件の `sendRun` として保存する |
| 日付判定 | 日本時間 `Asia/Tokyo` |
| フリーテキスト整形 | Geminiに自然な日本語への整形を指示する |

## 4. 対象外

- ユーザ情報への誕生日・記念日フィールド追加。
- ユーザごとの個別メッセージ生成。
- ユーザごとに異なるLINE本文の送信。
- 年齢、周年数の自動計算。
- Google Calendarなど外部カレンダー連携。
- 月間カレンダー形式の表示。
- 祝日、六曜、二十四節気など外部カレンダーデータの管理。
- 一括CSVインポート。

## 5. 画面仕様

### 5.1 ルーティング

カレンダー情報は独立した画面として追加する。

PCのタブ、スマホのハンバーガーメニューには `カレンダー情報` を追加する。並び順はPCとスマホで共通にする。

| 表示順 | 表示名 | URL | 備考 |
| --- | --- | --- | --- |
| 1 | 受信履歴 | `/` | 受信メッセージ一覧 |
| 2 | 送信履歴 | `/sent` | 手動送信、自動送信の履歴 |
| 3 | Cron履歴 | `/cron-runs` | Cron実行履歴 |
| 4 | ユーザ情報 | `/users` | 送信対象ユーザの選択 |
| 5 | メッセージ送信 | `/send` | 今日Geminiに渡る予定を確認する |
| 6 | カレンダー情報 | `/calendar` | 月日とイベント文を管理する |
| 7 | 管理画面 | `/settings` | 既存の管理画面 |

### 5.2 カレンダー情報画面

表示項目:

- 画面タイトル: `カレンダー情報`
- 説明文: `挨拶文に使う誕生日や記念日を、月日ごとに登録します。`
- 今日の予定サマリー。
- 登録済みイベント一覧。
- 一覧末尾の `＋` ボタン。

今日の予定サマリー:

```text
今日の予定: 千夏子の誕生日
```

当日イベントがない場合:

```text
今日の予定はありません。
```

### 5.3 行追加

`＋` ボタンは登録済みイベント一覧の最後の行の下、左端に表示する。

`＋` ボタンを押すと、一覧末尾に未保存の入力行を1件追加する。未保存行が表示中は、重複追加を避けるため `＋` ボタンを無効化する、または非表示にする。

保存すると、日付順に並び替えた一覧へ反映する。キャンセルすると未保存行を破棄し、`＋` ボタンを再表示する。

`＋` ボタンはアイコンボタンとして表示し、`aria-label` は `カレンダー情報を追加` にする。

入力項目:

| 項目 | 必須 | 仕様 |
| --- | --- | --- |
| 月日 | 必須 | `MM/DD` 形式。例: `07/29` |
| イベント | 必須 | 1文字から40文字。前後空白は保存時に削除 |
| 有効 | 任意 | 初期値ON |

入力例:

```text
月日: 07/29
イベント: 千夏子の誕生日
```

保存後は `07/29` のようにゼロ埋めした月日で一覧表示する。

### 5.4 登録済みイベント一覧

一覧は月日順、同日の中では作成順で表示する。

表示項目:

- 月日。
- イベント。
- 有効/無効。
- 編集。
- 削除。

表示例:

| 月日 | イベント | 状態 |
| --- | --- | --- |
| 07/29 | 千夏子の誕生日 | 有効 |
| 10/19 | 岳夫の誕生日 | 有効 |
| 10/31 | 由美子の誕生日 | 有効 |
| 11/09 | 岳夫と由美子の結婚記念日 | 有効 |

PCでは表形式で表示し、スマホではカード形式で表示する。スマホでも `＋` ボタンは最後のカードの下、左端に表示する。

### 5.5 編集

編集では月日、イベント、有効/無効を変更できる。

保存失敗時は画面にエラーを表示し、画面上の値を保存前の状態へ戻す。保存中は同じイベントの保存ボタンを無効化する。

### 5.6 削除

削除時は確認ダイアログを表示する。

確認文:

```text
このカレンダー情報を削除しますか？
```

削除失敗時は一覧から消さず、エラーを表示する。

### 5.7 メッセージ送信画面での表示

`/send` には、作成ボタンの近くに今日Geminiへ渡る予定を表示する。

当日イベントあり:

```text
今日の優先ネタ: 千夏子の誕生日
```

複数イベントあり:

```text
今日の優先ネタ: 千夏子の誕生日、岳夫と由美子の結婚記念日
```

当日イベントなし:

```text
今日の優先ネタはありません。
```

## 6. データ仕様

### 6.1 保存先

```text
lineAccounts/{lineAccountId}/calendarEvents/{eventId}
```

### 6.2 保存例

```json
{
  "createdAt": "...",
  "day": 29,
  "enabled": true,
  "eventId": "cal_...",
  "eventText": "千夏子の誕生日",
  "lineAccountId": "default",
  "month": 7,
  "monthDay": "07-29",
  "sortOrder": 0,
  "updatedAt": "..."
}
```

### 6.3 フィールド

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `eventId` | string | 必須 | ドキュメントIDと同じ値 |
| `lineAccountId` | string | 必須 | LINEアカウントID |
| `month` | number | 必須 | 1から12 |
| `day` | number | 必須 | 1から31 |
| `monthDay` | string | 必須 | `MM-DD` 形式 |
| `eventText` | string | 必須 | Geminiに渡すイベント文 |
| `enabled` | boolean | 必須 | Gemini連携対象にするか |
| `sortOrder` | number | 任意 | 同日内の表示順。未設定時は0 |
| `createdAt` | timestamp | 必須 | 作成日時 |
| `updatedAt` | timestamp | 必須 | 更新日時 |

### 6.4 正規化

- `monthDay` は `MM-DD` 形式で保存する。
- `eventText` は前後空白を削除して保存する。
- 連続する空白は1つに圧縮する。
- `eventText` は40文字以内にする。
- `lineAccountId` はログインセッションから取得し、リクエスト本文からは受け取らない。
- 同じ `monthDay` に複数の異なるイベントを登録できる。
- 同じ `monthDay` と同じ正規化後 `eventText` の完全重複は保存しない。

### 6.5 日付ルール

- `04/31`、`06/31`、`11/31` は保存不可。
- `02/30`、`02/31` は保存不可。
- `02/29` は保存可。
- 平年の `02/29` は当日一致しない。自動的に `02/28` や `03/01` には振り替えない。

## 7. API仕様

### 7.1 一覧取得

```text
GET /api/calendar-events
```

レスポンス:

```json
{
  "events": [
    {
      "day": 29,
      "enabled": true,
      "eventId": "cal_...",
      "eventText": "千夏子の誕生日",
      "lineAccountId": "default",
      "month": 7,
      "monthDay": "07-29"
    }
  ],
  "todayEvents": [
    {
      "eventText": "千夏子の誕生日",
      "monthDay": "07-29"
    }
  ]
}
```

### 7.2 追加

```text
POST /api/calendar-events
```

リクエスト:

```json
{
  "day": 29,
  "enabled": true,
  "eventText": "千夏子の誕生日",
  "month": 7
}
```

### 7.3 更新

```text
PATCH /api/calendar-events/{eventId}
```

リクエスト:

```json
{
  "day": 29,
  "enabled": true,
  "eventText": "千夏子の誕生日",
  "month": 7
}
```

### 7.4 削除

```text
DELETE /api/calendar-events/{eventId}
```

## 8. Gemini連携仕様

### 8.1 当日イベント取得

メッセージ作成前に、日本時間の月日から `monthDay` を作る。

```text
07-29
```

Firestoreでは `monthDay` が一致するイベントを取得する。`enabled: false` はアプリ側で除外する。複数イベントがある場合は、表示順で並べて `、` で連結する。

### 8.2 Geminiに渡す情報

当日イベントがある場合、プロンプトの【今日の情報】に追加する。

```text
・今日の大切な予定: 千夏子の誕生日
```

複数イベントの場合:

```text
・今日の大切な予定: 千夏子の誕生日、岳夫と由美子の結婚記念日
```

当日イベントがない場合は、この行を入れない。

### 8.3 プロンプトルール

Geminiプロンプトには以下のルールを追加する。

```text
今日の大切な予定がある場合は、誕生花、花言葉、天気、季節の話題よりも優先して本文の中心にしてください。
今日の大切な予定は、自然な日本語に整えてください。
人名と思われる名前には「さん」を付けてください。
例: 「千夏子の誕生日」→「今日は千夏子さんのお誕生日ですね。」
例: 「岳夫と由美子の結婚記念日」→「今日は岳夫さんと由美子さんの結婚記念日ですね。」
```

### 8.4 文字数

当日イベントがない場合は、既存の文字数ルールを維持する。

当日イベントがある場合は、誕生花、花言葉、天気、行動アドバイスも入るため、文字数上限を広げる。

| 条件 | 文字数 |
| --- | --- |
| 当日イベントなし | 60文字から95文字 |
| 当日イベントあり | 80文字から130文字 |

## 9. ログ・証跡

API失敗時は以下をログに残す。

- `requestId`
- `lineAccountId`
- `eventId`
- 操作種別: `list`、`create`、`update`、`delete`
- エラー概要

ログに残さないもの:

- Gemini APIキー。
- LINE channel secret。
- LINE channel access token。
- Cookie値。
- Push subscription keys。

`eventText` は個人情報を含む可能性があるため、通常ログには出さない。デバッグが必要な場合も先頭数文字に限定する。

## 10. 優先度

| 優先度 | 内容 |
| --- | --- |
| 致命 | 他の `lineAccountId` のカレンダー情報が表示、送信、Gemini連携される |
| 重大 | 当日イベントがあるのにGeminiへ渡らない、無効イベントが渡る、日付判定が日本時間とずれる |
| 重大 | フリーテキストがログに過剰出力される |
| 軽微 | 一覧の並び順が想定と異なる、文面の自然化がやや不自然 |

まず防ぐべき不具合は、他アカウントのカレンダー情報混入と、当日イベントの誤判定である。

### 11.5 実行順序・競合

| ID | 観点 | 意図 | 前提 | 手順 | 期待結果 |
| --- | --- | --- | --- | --- | --- |
| R-001 | 実行観点 | 保存中の二重クリックを防ぐこと | 保存処理中 | 保存ボタンを連打 | 重複作成されない |

## 12. 実装メモ

- `src/features/messages/server/gemini.ts` の `generateDailyGreetingMessage` に当日イベント情報を渡せるようにする。
- 手動生成APIとCron自動送信APIの両方で同じ当日イベント取得関数を使う。
- `src/features/messages/server/gemini.test.ts` では、プロンプトに `今日の大切な予定` と自然化ルールが含まれることを検証する。
- Firestoreクエリはまず `monthDay` で取得し、`enabled` の判定と並び替えはアプリ側で行う。
- `next-env.d.ts` はビルドや型チェックで更新されることがあるため、この機能のPRには必要な場合だけ含める。
